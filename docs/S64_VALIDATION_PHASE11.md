# Phase 11 — S-64 / Chart-1-style validation harness

Phase 11 adds an external validation harness on top of the Phase 10 command-level transcript infrastructure.

The goal is to support serious S-64 / Chart-1-style validation without making the WebGL renderer or screenshot comparison the first correctness boundary. The validation path remains:

```text
normalized ENC features
        ↓
S52PortrayalEngine
        ↓
S52DrawCommand list
        ↓
stable transcript
        ↓
expected transcript comparison
```

## Added APIs

Phase 11 adds these reusable classes under `s52-tests`:

```text
CommandValidationFixture
ValidationFixtureSource
ValidationFixtureParser
S64CommandValidationRunner
CommandValidationResult
S64ValidationReport
```

The runner validates draw commands with `DrawCommandValidator` before comparing transcripts.

## Fixture format

The fixture format is a small line-oriented text format. It is deliberately simple so external validation data can be generated by scripts without needing a JSON dependency in the common test harness.

Example:

```text
id=chart1-depth-danger
source=SyntheticChart1
description=Depth safety and danger validation.
settings.safetyDepthMeters=5.0
settings.safetyContourMeters=10.0
context.compilationScale=50000.0
context.displayScale=50000.0
feature=1001|DEPARE|Area|DRVAL1=D:0.0;DRVAL2=D:4.0|POLYGON(-74,40;-73.99,40;-73.99,40.01;-74,40)
expect:
{"kind":"area-fill",...}
```

Feature syntax:

```text
feature=id|OBJECT|Primitive|ATTR=VALUE;ATTR=VALUE|GEOMETRY
```

Supported value prefixes:

```text
I: integer
D: decimal
T: text
L: comma-separated list of prefixed values
EMPTY
```

Supported geometries use the same compact geometry strings as command transcripts:

```text
POINT(lon,lat)
MULTIPOINT(lon,lat;lon,lat)
LINESTRING(lon,lat;lon,lat)
POLYGON(lon,lat;lon,lat;lon,lat)
```

## Included synthetic fixtures

The repository includes three synthetic validation resources:

```text
validation/chart1-depth-danger.s52v
validation/s64-display-settings.s52v
validation/s64-overlay-quality.s52v
```

They cover:

- depth area / contour / sounding safety behavior
- dangerous wreck and obstruction symbols
- light graphics with text and sounding suppression
- data coverage, restricted area, and quality overlays

## Why command-level first?

Pixel-level validation is useful later, but it is fragile early because fonts, anti-aliasing, GPU drivers, and symbol rasterization can produce harmless visual differences. Command-level validation proves that the S-52 portrayal decision is correct before the WebGL backend is tested visually.

## Current limitation

The included fixtures are synthetic. The harness is ready for external S-64 / Chart-1-derived normalized fixtures, but official test data is not bundled.
